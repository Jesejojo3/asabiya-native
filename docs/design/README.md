# Diseño de producto — Asabiya

Esta carpeta reúne la **visión conceptual** del proyecto, no una descripción de todas las funciones implementadas.

- [Visión fundacional](VISION.md): identidad, experiencia del observador, Tierra real y continuidad histórica.
- [Principios de diseño](DESIGN_PRINCIPLES.md): reglas de coherencia para proponer, construir y validar funcionalidades.
- [Roadmap conceptual](ROADMAP.md): etapas, dependencias, criterios de aceptación y límites del alcance.

## Cómo utilizar estos documentos

1. Antes de desarrollar una función nueva, contrastarla con la visión y los principios.
2. Usar el roadmap para separar **existente**, **pendiente de validar** y **propuesto**.
3. Mantener la documentación técnica y sus contratos en sus carpetas respectivas; esta carpeta no sustituye las especificaciones de Go, Godot, el protocolo ni las pruebas.
4. Modificar esta visión mediante cambios explícitos, revisables y documentados, no como efecto secundario de una optimización.

**Decisiones conceptuales acordadas:** simulación principalmente observacional; intervención opcional; Tierra real como escenario principal; atlas 3D plano inspirado en la navegabilidad de juegos de Paradox; historia alternativa emergente; continuidad entre épocas y memoria material del territorio.

**Cuestiones todavía abiertas:** fecha y población iniciales, catálogo/licencias/resolución del atlas terrestre, definición de provincias o celdas geográficas, alcance de intervenciones, detalle de cronologías y límites de simulación.

**Importante:** la v0.6 HTML es una referencia preservada y el cliente nativo sigue en desarrollo. El atlas terrestre y las eras futuristas aquí descritos son objetivos de producto, **no funcionalidades certificadas**.
